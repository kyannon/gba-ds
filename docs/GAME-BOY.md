# Game Boy and Game Boy Color games (issue #77)

Status: merged into `dev` (v1.6.1.1). Held for a later release: the Game Boy Color palette submenu / custom palettes (`claude/issue-77-held-phases.md` in the project). Written as the work went, on the branch `issue-77`: Phase 1 of the roadmap (`claude/issue-77-gb-gbc-roadmap.md` in the project) is done: the GB core is built in and a GB / GBC ROM starts and plays. The game list part of Phase 2 is done too (so a game can be started from the device's menu). The idle grey second screen (GB-3) is done, and Phase 3's first step: Game Boy size and scale (GB-2, GB-2a). Phase 3's second step, palettes and dual-mode games (GB-6, GB-7), is done. The third, color correction and ghosting (GB-8, GB-9), is done; the fourth, the shader and Dot matrix (GB-10), is built. Not done yet: the rest of Phase 2 (dump checksums, other launchers), the rest of the display options (Phase 3: colour correction, ghosting, the dot-matrix look; the plan is `claude/issue-77-display-options-proposal.md` in the project), saves / cheats / RetroArch states (Phase 4), ES-DE / BananaOS / Android launch, RetroAchievements and the wiki (Phase 5).

This is an extension of the idea behind GBA DS (wiki/Philosophy.md, principle 1: a Game Boy Advance with two screens). A real GBA played Game Boy and Game Boy Color cartridges itself, so GBA DS does too: **on one screen first**, with the other idle. These are the platform's rules, in the player's terms; the rule comes first and the code follows it. They sit beside the [general rules](games/README.md#general-rules), which hold for these games as well, so far as they apply.

| | |
|---|---|
| Games | any `.gb` / `.gbc` ROM mGBA's GB core runs (no per-game profiles) |
| Code | `src/emu.c` (`emu_open`: the core's platform, the model and colour defaults, the picture's place; `gba_of`: the GBA-only parts skip GB games) |
| Test ROMs | `tools/make_gb_test_rom.py OUTDIR` makes `gbads-test.gb` and `gbads-test.gbc` (stripes, scrolling, a tone, A inverts the DMG palette), no copyrighted code |
| Tests | none yet (Phase 5; GB cases with Phase 3's first step) |

## Rules

**GB-1. Played as the GBA played them.** A Game Boy or Game Boy Color game runs on the Game Boy Color hardware inside the GBA (mGBA's `AGB` model), whatever the cartridge: not as a plain Game Boy, and not as a Super Game Boy with its border (GB-11 plays a game that supports one as a Super Game Boy, still without the border; GB-12 adds the border when asked to). A game made for the plain Game Boy shows in the colours a Game Boy Color gave it (mGBA's table of the colour boot ROM's palettes; a game it doesn't list is in shades of grey), except a game that supports the Super Game Boy, which shows the colours it was made with for one (GB-11). GB-6 and GB-7 are the settings that change this; with them left alone, this is how it plays.

**GB-2. The picture.** By default the game's 160x144 picture is shown at the GBA's own pixel size (one game pixel to one GBA pixel, like every GBA game, GEN-5), centred in the 240x160 screen; the rest of the screen is black ("GBA frame"). **Game Boy screen** (Display > Game Boy: Size) is an exception to the philosophy's first principle, asked for by the owner: the 160x144 picture is the whole frame, as a Game Boy's own screen, and Game Boy scale decides how it fills the screen (below). The GBA frame stays the default and is never changed by the other.

**GB-2a. Game Boy scale.** With the Game Boy screen size, the picture fills the game's screen one of three ways: *Pixel Perfect* (the largest whole number of screen pixels to a game pixel that fits: 5x on the RG DS Plus's 1024x768 screens, 3x on the RG DS's 640x480), *Fit* (as large as fits with the picture's own 10:9 shape: 853x768 and 533x480) or *Stretch* (the whole screen, so wider than the Game Boy's own shape). There is no Zoom: it would be the same as Fit on every landscape screen. The shader (the LCD grid and the others), the generated bezel, overlays, the FPS counter and messages follow the picture's size and place; a game pixel is a grid cell. The GBA frame's scale (Display > Game screen scale) is not used while the Game Boy screen is. The second screen stays as GB-3 says, in either size. The quick bar, the pause menu and touch work in the GBA frame's place as before.

**GB-6. Palette.** For a game that runs in monochrome (made for the plain Game Boy, or a dual-mode game kept in monochrome by GB-7), Display > Palette picks its four shades: *Game's own* (the colours the game was made with: a game that supports the Super Game Boy has its Super Game Boy colours, GB-11; any other the Game Boy Color's palette for that game, grey if it has none; the default), *DMG* (the first Game Boy's greens), *Pocket* (the Game Boy Pocket's pale grey-green), *Light* (the Game Boy Light's blue-green backlight), *Grayscale* (white to black) or *Super Game Boy* (the same as Game's own for a game that supports the Super Game Boy, GB-11; any other game keeps Game's own colours). The choice colours the whole picture the same way: background, window and sprites. A game made for the Game Boy Color alone has its own colours and is not changed. The change counts from the next start of the game, so leaving the menu with it changed asks first: *Restart now* starts the game again from the top (not from a resume point, which would bring the old colours back), or *Discard changes* puts the setting back and the game goes on as it was (B goes back to the menu). The row says "Restart required" while it is changed. The row is greyed out, with the reason, for a game made for the Game Boy Color alone and for a dual-mode game kept in colour.

**GB-7. Dual-mode games.** A game made to run either on a Game Boy or in colour on a Game Boy Color (Pokémon Gold and Silver, for example) plays in colour by default, as the GBA ran it. Display > Dual-mode games set to *In monochrome* plays it as on a plain Game Boy instead, with GB-6's palette. It counts from the next start of the game, and asks to restart, as GB-6 says. Games made for one of the two only are not affected, and the row is greyed out for them.

**GB-8. Color correction.** Display > Game Boy color correction for a Game Boy / Game Boy Color game: *As GBA* (the default: follows Display > Color correction, on or off, as it does for a GBA game), *Off* (the colours the game draws), *Game Boy Color* (the washed, cross-mixed colours of a Game Boy Color's screen) or *Game Boy Advance* (the GBA's screen, as the GBA's own Color correction). It changes how the picture looks and nothing else, in the game and in screenshots as the GBA's does. The Game Boy Color's numbers are a first guess to be tuned after seeing them on the device. It applies at once.

**GB-9. Ghosting.** Display > Game Boy ghosting for a Game Boy / Game Boy Color game: *As GBA* (the default: follows Display > LCD ghosting, on as *Light*), *Off*, *Light* (each frame shown half and half with the one before, as the GBA's), *Smart* (only a thing that flickers, shown one frame and gone the next, is blended: scrolling stays sharp) or *Strong* (each frame slowly takes over from the last, over about three frames, as the first Game Boy's slow screen did). It applies at once.

**GB-10. Shader.** Display > Game Boy shader for a Game Boy / Game Boy Color game: *As GBA* (the default: follows Display > Shader, strength included), *Off*, *LCD Grid*, *Scanlines*, *Soft Cells* (the GBA's own patterns, laid one cell to a Game Boy pixel and as strong as Display > Strength says) or *Dot matrix*: the LCD Grid, and on top of it the faint shadow a Game Boy's screen put down and to the right behind anything darker than its surroundings. It changes how the picture looks and nothing else. It applies at once. With a choice of its own, the shader hotkey turns the Game Boy's pattern off and on (Dot matrix when it comes back). The grid of Dot matrix is the same on dark and light pixels (a first version; the real screen's shows mostly on dark ones).

**GB-11. Super Game Boy colours.** A game that supports the Super Game Boy (its cartridge says so: Castlevania Legends, Donkey Kong (1994) and the other "SGB Enhanced" games) is played as a Super Game Boy would play it, so it shows the colours it was made with: the game asks the Super Game Boy for its colours and gets them (Castlevania Legends: the red and gold title, not grey). This is what *Game's own* means for such a game (GB-6), and the *Super Game Boy* palette gives the same. The picture is the 160x144 of GB-2, with no border unless GB-12 asks for it. A game that does not support the Super Game Boy is not changed by any of this. A game that supports it but sends no colours stays in shades of grey, as on a Super Game Boy. A dual-mode game that supports it (GB-7) takes the Super Game Boy's colours only while it is kept in monochrome; kept in colour it plays in colour. A game made for the Game Boy Color alone is not changed. Choosing DMG, Pocket, Light or Grayscale (GB-6) plays the game on the Game Boy Color hardware with those shades instead. The game plays on the Super Game Boy's hardware, so a resume point made before (or under another palette) is not loaded: the game starts over, and says so (GB-6).

**GB-12. Super Game Boy border.** Display > Game Boy border, for a game that supports the Super Game Boy (GB-11): *None* (the default) or *Super Game Boy*, which shows the game's own border around its picture, as a Super Game Boy did. The picture is then 256x224 (the border with the game's 160x144 in the middle) and takes the place of the GBA frame: it is shown at the Game Boy screen's size and scale (GB-2, GB-2a: Display > Game Boy scale picks Pixel Perfect, Fit or Stretch, whatever Display > Game Boy size says). A game draws its border a moment after it starts; until it does, the border area is black (mGBA's own frame, which says "mGBA", is never shown). A game that never sends one keeps a black border. The colours are the Super Game Boy's (GB-11), so Display > Game Boy palette is greyed out, with the reason, while the border is on. Shader, ghosting and color correction act on the game's own 160x144 picture as before; the border keeps its colours. The second screen stays idle (GB-3). The row is greyed out, with the reason, for a game that does not support the Super Game Boy, for a game made for the Game Boy Color alone and for a dual-mode game kept in colour (GB-7). Like the palette (GB-6) it counts from the next start of the game: leaving the menu with it changed asks first (*Restart now* or *Discard changes*), and a resume point made without it, or with it, is not loaded the other way round.

**GB-3. The second screen.** The game is on one screen only. The second screen is idle: dark grey, as GEN-1 says for a screen with nothing live to show, with no logo (logos come later). It is drawn as the logo's idle screen is (the same picture size, scaling and LCD grid), so its edges match the game screen's (`game.c` `make_logo_canvas`, `draw_game`); with one screen there is nothing to show.

**GB-4. Not supported means "single screen only".** A Game Boy / Game Boy Color game is listed like a GBA game with no second-screen profile: only with "Show all" on, marked "Single screen only: plays normally". "Supported" means a game with dual-screen support, not a game the emulator can run. The list takes `.gb`, `.gbc` (and `.sgb`, `.dmg`, `.cgb`) files and the same inside a `.zip` / `.7z`. A games folder named `gba` has its `gb` and `gbc` folders beside it read the same way (subfolders too, in the folder's own letter case: `GBA` / `GB` / `GBC`), so those games don't have to be moved into the GBA folder; nothing to set up, and a folder that isn't there is simply skipped (`library.c` `scan_siblings`).

**GB-5. The game is never touched.** As GEN-2: nothing is paused, sent input or changed for the second screen. (There is nothing on the second screen to capture yet.)

**GB-13. Pictures of the game.** The pictures saved of a Game Boy game show what the screen shows: the game's own 160x144 at the Game Boy screen size (GB-2), the 256x224 with the border when the Super Game Boy border is on (GB-12), the GBA frame with the picture in it when the GBA frame is the size. That is the picture under the game's name in the game list after a resume point is made, and the picture beside a state in RetroArch's folder. Take Screenshot saves both screens as displayed (it always has: with the Game Boy size or the border it shows them). The game list draws a picture in its own shape, not squeezed to the GBA frame's. Shader, ghosting, colour correction and the dot matrix are in the picture as they are in the game; the shader's grid and the bezel are not (a screenshot has them, being the screen).

**GB-14. A modified ROM says so.** Under a Game Boy / Game Boy Color game's logo in the game list, a ROM that is not one of the dumps in No-Intro's Game Boy and Game Boy Color lists (every dump in them: revisions, prototypes, unlicensed games, collections) says *Modified ROM: not a known dump* (*Patched ROM: not a known dump* when a patch beside it made it so). A hack, a translation, a trimmed or a bad dump is not a known dump; so is a ROM too new for the list. It is only a note: the game plays as any other, and a known dump says nothing. (A GBA game's note says its second screen may not work: a Game Boy game has none to lose.) The list is `src/dumps_gb_data.h`, made by `tools/make_dumps.py --gb-dat`; the log's `ROM:` line and a bug report's `ROM dump:` say the same.

## Known limitations (so far)

- The palette and dual-mode rows (GB-6, GB-7) count from the next start: Leaving the menu asks to restart now (from the top) or discard the change. A resume point remembers the colours it was made with: if they differ from the settings when the game starts, the game starts over instead of resuming (it says so). The shades of DMG, Pocket and Light are the first guesses and may change after seeing them on the device. A game made for the Game Boy Color alone is never changed by them.
- The Game Boy size and scale rows sit at the top of the pause menu's Display page for Game Boy games, and in Settings > Display (they have no effect on GBA games). Scale is shown even while the size is the GBA frame.
- ES-DE / BananaOS / Android launchers don't hand `.gb` / `.gbc` games to GBA DS yet (Phase 5): start them from GBA DS's own game list.
- A Game Boy game has no 4-letter code like a GBA game's, so it gets its own from its header: `g` (plain Game Boy) or `c` (works on the Game Boy Color) and 3 characters, in lower case (`src/emu.c` `emu_rom_code`). The patch folder is named from its title and that code.
- Battery saves, RTC games (Pokémon Gold / Silver / Crystal), cheats, RetroAchievements, RetroArch's shared states: not checked or not available yet. Rumble, the Game Boy Camera and the link cable are not planned.
- A game played as a Super Game Boy (GB-11) runs at the GBA's pace like every Game Boy game here, about 2 % slower than a real Super Game Boy's clock, and its sound is a little lower to match. The Super Game Boy's own sound effects and its controller features are not played (the border is GB-12's).
- mGBA's Game Boy core is mGBA's: timing-sensitive games may show problems that belong to it.
