# Translations (the interface's language)

GBA DS's menus, game list and messages are English in the code. A language is a
`.po` file in `assets/i18n/`; the build turns them into tables inside the program
(so they ship in the zip and the APK with everything else), and the player picks
one in **Settings > System > Language** (or leaves it on Automatic, which follows
the system). The change is immediate, no restart. A string that has no
translation reads in English, so a language that's only partly done is usable.

Status: the infrastructure is in (this branch, `app-translation-support`); the
first catalogues (Spanish, German, Chinese, Japanese) come in later steps. The
plan and the decisions behind it are in the project's
`claude/app-translation-support-progress.md`.

## How a string is translated

English is the key. Two places translate:

1. **As it is drawn.** `ui.c`'s `ui_label`, `ui_font_text`, `ui_font_wrap*` and the
   width functions look the string up (`tr()`), so any English literal handed to
   them is translated if the catalogue has it. A game's title (`ui_title_block`)
   is the player's own and is never looked up.
2. **Where the code builds a sentence.** A number in a sentence, a value in a row:
   the format is looked up where it's built, then filled in.

```c
snprintf(buf, n, tr("Slot %d: Empty"), slot);
snprintf(buf, n, trn("Found %d game", "Found %d games", count), count);
ui_label(scr, x, y, cap, trc("direction", "Left"), color);   /* one word, two meanings */
static const char* pages[] = { N_("Cheats"), N_("Patches") }; /* a table: tr() runs when it's drawn */
```

- `tr(en)`, `trc(ctx, en)`: the text; `trn(one, other, n)`, `trnc(ctx, one, other, n)`:
  the format for n in the language's plural rule. English text comes back when
  there is no translation.
- `N_("...")`, `NC_("ctx", "...")` mark a string in a table so the extractor
  finds it; they return it unchanged.
- A format may **reorder** its arguments (`"Auf %2$s: %1$s"`) but must use all
  of English's, with the same types. `tools/i18n.py check` says if not.
- Don't build a sentence by gluing translated pieces: give the whole sentence to
  `tr()` so a language can order it as it needs.
- The extractor reads: the macros above, a literal passed straight to a drawing call
  (`DRAW_CALLS` in `tools/i18n.py`), and the rows of `config.c`'s settings tables by
  their shape. Anything else (a literal in a table that is drawn later, a format
  built by `snprintf` without `tr`) has to be marked, or it stays English.

## Files

| File | What |
|---|---|
| `assets/i18n/gba-ds.pot` | the template: every string the code can say. Generated (`tools/i18n.py pot`), committed. |
| `assets/i18n/<code>.po` | a language; the source of truth. `de.po`, `es.po`, `fr.po`, `it.po`, `pt.po`, `ja.po`, `ko.po`, `zh_CN.po`, `zh_TW.po`. |
| `src/i18n_data.c`, `i18n_data.h` | the tables, generated by `tools/i18n.py compile`. Never edit or merge by hand: regenerate. |
| `src/i18n.c`, `i18n.h` | lookup, plural rules, which language `auto` means. |
| `tools/i18n.py` | extract, check, compile. |
| `tools/test_i18n.c` | `make test-i18n`: locale matching, lookups, plurals, the font fallback. |

A `.po` file's header says what the app needs to know:

```
msgid ""
msgstr ""
"Language: de\n"                      (= the file's name)
"Content-Type: text/plain; charset=UTF-8\n"
"Plural-Forms: nplurals=2; plural=(n != 1);\n"
"X-GBADS-Autonym: Deutsch\n"          (its own name, as Settings lists it)
"X-GBADS-Script: latin\n"             (which fonts: see below)
"X-GBADS-Status: machine\n"           (machine / reviewed)
"X-GBADS-Locales: de_AT de_CH\n"      (other system locales that mean it)
```

`X-GBADS-Status: machine` marks a catalogue written by a machine and not yet read by a
person who speaks the language; change it to `reviewed` when someone has (their
name and the date go in a `# Reviewed by` comment). The plural rules the app
implements are listed in `tools/i18n.py` (`PLURAL_RULES`) and `src/i18n.c`
(`i18n_plural_index`); a language that needs another one adds it in both.

## Commands

```sh
tools/i18n.py pot       # the template from the source (after adding or changing strings)
tools/i18n.py check     # the catalogues against the template: missing, obsolete, fuzzy,
                        # formats that don't match, plurals, headers, an old template
tools/i18n.py compile   # src/i18n_data.[ch]
tools/i18n.py all       # all three: run it, then commit the .pot and the generated files
make test-i18n
```

`check` runs in CI (`.github/workflows/i18n.yml`) and fails on an out-of-date template
or tables. Translators don't need a toolchain: edit the `.po` (Poedit, Weblate, a text
editor) and open a pull request; the tables are regenerated for them.

## Finding clipping and unmarked strings

There is no pseudo-language any more (it was a development aid, removed once every
string was marked). To look for clipping, switch to German or French (the longest) and
walk the menus; a string that stays English in a translated language was never marked
(or has no translation yet: `tools/i18n.py check` lists those).

## Fonts and scripts

The interface is drawn in Jost. Every character comes from the first font in a chain
that has it (`textfont.c`): Jost first, then the fallback fonts the language's script
needs (`tf_fallback_add`, set up by `ui_language_changed`). So Latin text (game titles,
numbers, accents like the é of Pokémon) stays in Jost in every language, and a script
Jost lacks (Chinese, Japanese, Korean, Greek, Cyrillic in some cases) comes from its own
font, cut down to the characters the catalogues use. Text is scaled by each font's
capital height so two fonts sit together on one baseline.

Step 1 has only the Latin script; each later script adds its font (an OFL subset in
`assets/fonts/`, `tools/embed_fonts.py` into `src/fonts_data.c`), its name in
`SCRIPTS` (`tools/i18n.py`) and `SCRIPT_*` (`src/i18n.h`), and its fallback faces in
`ui_language_changed`. Not supported yet: right-to-left text and scripts that need
shaping (Arabic, Hebrew, Thai, Devanagari): `stb_truetype` doesn't do either.

## What stays English

The player's own data (game titles, paths, file names), the log, a bug report's
`info.txt`, RetroAchievements' own text (names, descriptions, the server's errors), the
pixel font's FPS counter and version number.

## Adding a language

1. `cp assets/i18n/gba-ds.pot assets/i18n/<code>.po`, fill in the header and the `msgstr`s
   (a machine pass first is fine: leave the status `machine`).
2. `tools/i18n.py all`; fix what `check` says; look at the game list, Settings and the
   pause menu with the language chosen (the long strings are where it breaks).
3. If its script needs a font, see above.
4. Commit the `.po` and the regenerated files.

## Status (step 2)

- All interface strings are marked (686); the extractor reads draw calls, ternaries and byte escapes.
- Spanish (`es.po`) and German (`de.po`) are machine translations (`X-GBADS-Status: machine`), not yet reviewed by native speakers.
- Layout checked in es, de on the pause menu and Settings; regression suite 1456/1456.

## Chinese (step 3)

- `zh_CN.po` (Simplified) and `zh_TW.po` (Traditional) come from PR #62 by DokiOnjouji (the TSVs, converted), with the strings the PR lacked added by hand. They are marked `machine` until a second speaker reviews them.
- Fonts: Noto Sans SC and TC subsets (`assets/fonts/NotoSans{SC,TC}-{Regular,Bold}-subset.ttf`, OFL) made by `tools/make_zh_font.py` from the catalogues' characters plus every language's own name. Run it again when a Chinese string gets a new character (it needs the variable sources, `NotoSansSC[wght].ttf` / `NotoSansTC[wght].ttf` from google/fonts, in `assets/fonts/`; they're git-ignored), then `tools/embed_fonts.py` and `tools/i18n.py all`.
- The faces are fallbacks behind Jost (`ui_language_changed`): Simplified is chained for every language (so the Language list's names draw), Traditional first for `zh_TW`.
- Line breaking (`ui.c piece_end`): a Chinese character is a piece; closing punctuation stays with the character before it, opening marks with the one after.
- Known: only the characters in the catalogues are in the fonts, so Chinese ROM file names or other text outside them draw as boxes.

## Japanese (step 4)

- `ja.po` is a machine translation (`X-GBADS-Status: machine`), script `jp`. Dates use the reordered arguments (`%4$d年%2$s%3$d日`, months "4月").
- Font: Noto Sans JP subset (OFL, `NotoSansJP-{Regular,Bold}-subset.ttf`, all kana plus the kanji the catalogue uses) from `tools/make_zh_font.py` (source `NotoSansJP[wght].ttf` from google/fonts in `assets/fonts/`, git-ignored). For `ja` it is chained first, then Simplified Chinese for the Language list's names.
- Line breaking: the long-vowel mark, the middle dot and the small kana stay with the kana before them (`cp_no_start`).

## French, Italian, Portuguese, Korean (step 5)

- `fr.po`, `it.po`, `pt.po` (Brazilian Portuguese; locales `pt_BR pt_PT`) and `ko.po` are machine translations (`X-GBADS-Status: machine`). French's plural rule is `n > 1`, Korean's has one form. Dates: Korean `%4$d년 %2$s %3$d일`, months "4월".
- Korean needs its own script: `ko` in `SCRIPTS` (tools/i18n.py) and `SCRIPT_KO` (src/i18n.h); Noto Sans KR subset (OFL, `NotoSansKR-{Regular,Bold}-subset.ttf`) from `tools/make_zh_font.py` (source `NotoSansKR[wght].ttf` from google/fonts `ofl/notosanskr`, git-ignored). It is chained first for `ko`, then Simplified Chinese; for every other language it is chained last, so the Language list draws 한국어. Hangul isn't in `cp_cjk` (ui.c), so Korean wraps at spaces.
- The Android launcher's strings (`android/app/src/main/res/values-<locale>/strings.xml`: es, de, fr, it, pt, ja, ko, zh-rCN, zh-rTW) are machine translations too; `app_name` stays in `values/`. They are Android resources, not part of the `.po` pipeline, so a change to `values/strings.xml` needs the other nine updated by hand.
- Wiki: `wiki/Languages.md` (for players and translators).

## The first-run question (issue #92)

On a first install (GEN-18 in `docs/games/README.md`) `library.c`'s `library_language_ask` lists every catalogue (all but `I18N_TEST` ones) by its `X-GBADS-Autonym`, and writes each one's "Language" and "machine translated" in that language with `i18n_tr_in(code, en)`, whatever language is in use; `ui_font_text_as_is` draws text that mustn't be translated (the names, the English lines). A new language appears there by itself; its own "Language" and "machine translated" should be translated for it to read right. Those names and notes are drawn in the bold weight, whose CJK faces hold whole name sets.
